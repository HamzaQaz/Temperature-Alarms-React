About this comp

Audience
The technicians first thing in the morning, and anyone who has to answer "what happened overnight?" for a supervisor.
Job
Read the night in order: which Device went into which Condition, how bad it got, when it started and ended, and jump to that day's History to see the curve.
Key decision
Two readings of one log. On the left, each incident as a sentence with its numbers; on the right, the same incident as a span on a shared 18:00 to 08:00 ruler, segmented by level, so overlaps and the worst stretch of the night are visible without reading. Chronological, oldest first, so a new incident arrives at the bottom like the next line in a log.
Relies on
  • Say what happened, with the numbers: peak, start, end, duration on every row.
  • Two Reds: the critical stretch is Critical Fill, with no text on it.
  • Signature motion: a new row rises 6px and takes the Reading-landed wash; reduced motion keeps only the fade.
  • History links by Device and day, so the chart stays the place for curves.
Would change
  • A new page and nav item (Incidents). The span bars are a new chart form for DESIGN.md.
  • Level segments use the signal tints as fills without text, an extension of the badge tints.
Server needs
An incident log the backend writes when a Condition starts, changes level, and ends, with the peak Reading. Today Conditions are computed for the latest Reading only, so this is the comp with the largest backend cost.
