# 18 — Run the whole system with Docker Compose

**What to build:**
An Operator clones the repo, copies `.env.example` to `.env`, sets two tokens and a database password, and `docker compose up -d --build` gives them the dashboard on one port with a persistent database, on a laptop or on the district server alike. Decided in the grilling of 2026-09-09; the trade-offs are in ADR 0005.

**Blocked by:** 14 — Docs, deploy, and end-to-end verification

**Status:** ready-for-human

- [x] `compose.yaml` at the repo root defines `db` (MySQL 8.4, named volume, healthcheck, port not published), `api` (built from `backend/Dockerfile`, one instance, healthcheck on `/api/health`, not published, waits for `db` healthy), and `web` (built from `frontend/Dockerfile`, nginx serving the built frontend and proxying `/api/` with the SSE settings, published on `WEB_PORT`, default 80); all `restart: unless-stopped` with log rotation capped
- [x] A root `.env.example` carries `ADMIN_TOKEN`, `DEVICE_TOKEN`, `DB_PASSWORD` (required; Compose refuses to start naming any that is unset, with an `openssl rand -hex 32` hint), `WEB_PORT`, and the backend's optional settings including a commented `LEGACY_TIME_ZONE`; `.env` is gitignored
- [x] Both Dockerfiles are multi-stage on Node 22 Alpine: the backend image runs `dist/index.js` as a non-root user and carries `scripts/mock-device.mjs`; the frontend image builds with no API address and serves from nginx
- [x] The frontend treats an unset `VITE_API_URL` as same-origin; local dev with `.env` pointing at port 3001 is unchanged
- [x] `DEPLOYMENT.md` leads with Compose: setup, first run, upgrades (`git pull` and rebuild), backups and restore through `docker compose exec db`, migrating an old database in (dump, restore into the volume, `LEGACY_TIME_ZONE`, then `migrate:legacy` through `exec`), and TLS in front of the stack; the manual PM2 and nginx path stays below as the fallback
- [x] README's local development, deployment, and firmware sections say the stack is the way to run it, that boards point `SERVER_URL` at `http://<host>` (the port only if changed), and how to run the virtual Device against the stack with `docker compose exec`
- [ ] Verified from a clean clone against Docker Desktop: build, `up`, health, the ticket 14 end-to-end walk through the published port (Settings, a Reading with the Device token, the card live over SSE through nginx, History, wrong tokens refused), the virtual Device posting through `exec`, data surviving `down` and `up`, and `down -v` wiping it
- [x] Lint, typecheck, and both test suites still pass; `backend/docker-compose.yml` and `npm run test:db` are unchanged

## Comments

**2026-09-09 — built; the Docker walk is left to a human.** This machine has no Docker (see the memory note on the scratch MySQL), so the sixth box stays open. What was verified here instead:

- **`compose.yaml`** parses (PyYAML). `db` is `mysql:8.4` on the `db-data` volume, healthcheck `mysqladmin ping` as root over TCP (so the init-time socket-only server does not count), no `ports`. `api` builds from `backend/Dockerfile`, waits for `db` healthy, healthcheck is a `node -e fetch` of `/api/health` (the runtime image has no curl), no `ports`, no `CORS_ORIGIN` because the page's own origin serves `/api/`. `web` builds from `frontend/Dockerfile`, waits for `api` healthy, publishes `${WEB_PORT:-80}:80`. All three `restart: unless-stopped` with a shared `json-file` 10m×3 logging anchor. The three secrets use `${VAR:?Set VAR in .env (openssl rand -hex 32)}`. `MYSQL_ROOT_PASSWORD` is `DB_PASSWORD` too, so backups and restores through `exec db` need no fourth secret.
- **`frontend/nginx.conf`** passes `nginx -t` with the host's nginx 1.x (the only complaint is binding :80 unprivileged). It resolves `api` through Compose's DNS at request time (`resolver 127.0.0.11`, `set $api`), so nginx starts before `api` and follows it to a new address after a rebuild; the `/api/` block carries the SSE settings from the manual guide verbatim.
- **Same-origin frontend.** New seam `frontend/src/lib/apiBase.ts` (`apiBaseUrl`): unset or blank `VITE_API_URL` is `''`, an address loses its trailing slash. Written test-first (`apiBase.test.ts`, 2 cases, red then green). `npm run build` with `.env` absent and `VITE_API_URL` unset produced a bundle with no backend address in it (the only `3001` hit is a Unicode range in React). `frontend/.env.example` keeps `VITE_API_URL=http://localhost:3001` for dev, so the dev server is unchanged.
- **Images.** Both Dockerfiles are two-stage on `node:22-alpine`; the backend runtime installs `--omit=dev`, copies `dist/` and `scripts/` (the virtual Device), and runs `dist/index.js` as `node`; the frontend build stage copies the tree minus `.env*`, `node_modules`, `dist` (`.dockerignore`) and the runtime is `nginx:1.28-alpine`. The lockfile carries the musl builds of rollup, oxide, and lightningcss, so `npm ci` on Alpine should resolve them; unverified without Docker. `mock-device.mjs` now defaults its token to `$DEVICE_TOKEN` and its port to `$PORT`, so `docker compose exec api node scripts/mock-device.mjs --hostname ESP_xxxxxx` needs no other flag.
- **Docs.** `DEPLOYMENT.md` opens with the stack (service table, setup with the three-secret table, first run with the ticket 14 curl walk through the published port and the `exec` virtual Device, upgrades, backups and restore with `exec -T`, migrating an old database in, TLS in front via Caddy or host nginx with `WEB_PORT=127.0.0.1:8080`); the legacy-table section is shared by both paths; the manual PM2 and nginx path is demoted to `###` headings under "Manual install (without Docker)". README: ADR 0005 in the list, `compose.yaml` and `.env.example` in the layout, "Run the stack" leads local development, the frontend section explains unset `VITE_API_URL`, the virtual Device has its `exec` form, flashing step 1 says `http://<host>` (port only if `WEB_PORT` changed), and Deployment points at the stack. `config.example.h` says the same.
- **Checks.** Backend `npm run typecheck` and `npm test` (159 pass) against the scratch MySQL on :3307; frontend `npm test` (5 pass), `npm run lint`, `npm run typecheck`. `backend/docker-compose.yml` and `npm run test:db` untouched.

**Code review** (Standards and Spec axes): the Standards agent caught a real one. Browsers send `Origin` on every non-GET request, same-origin included, and `cors.ts` allowed only the configured `CORS_ORIGIN`, so every Settings change through the stack would have been 403. Fixed test-first (`campuses.test.ts`: a POST with `Origin` equal to the server's own URL is 201 with no `CORS_ORIGIN`, a foreign one stays 403): the middleware now also accepts an Origin whose host equals the request's `Host`, and `frontend/nginx.conf` forwards `Host $http_host` so the port survives. Also fixed: the README's ADR 0005 link (wrong filename), the health body in the first-run walk (`"database":"connected"`), a README claim that the test-database user could create a dev database, "boards" for Device in two new lines, and `location ^~ /api/` so the asset regex can never outrank the proxy. Left alone: `PORT` and `CORS_ORIGIN` are absent from the root `.env.example` on purpose (meaningless inside the stack), and `web` waits for `api` healthy on top of resolving it at request time (orderly first `up`; survival afterwards).

**Open for a human with Docker Desktop:** from a clean clone, `cp .env.example .env`, set the three secrets, `docker compose up -d --build`, `docker compose ps` healthy, then the first-run walk in `DEPLOYMENT.md` (Settings, a Reading with the Device token, the card live over SSE through nginx, History, wrong tokens refused), the virtual Device through `exec`, data surviving `down` then `up`, and `down -v` wiping it. Also try `docker compose up` with one secret blank to see the named refusal. If the frontend image fails at `npm ci` on Alpine, the fix is `node:22-slim` in `frontend/Dockerfile`.
