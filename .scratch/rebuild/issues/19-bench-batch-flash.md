# 19 — Flash and check a batch of Devices from the bench

**What to build:**
A technician with a box of NodeMCU boards, a USB hub, and the inventory spreadsheet runs one watcher on Windows, plugs boards in, and each one comes out identified against the sheet, registered, flashed with the one exported binary, and bench-checked against the live server, with a log that reconciles the box to the sheet. Decided in the grilling of 2026-09-10 for the batch of 98 boards; the sheet is `device_log - device_log.csv` (92 boards with hostname and MAC, no Campus or Closet, so at least six boards are off the list).

**Blocked by:** 18 — Run the whole system with Docker Compose

**Status:** done

- [x] `arduino/bench.py`, Python 3 on Windows, needs only `esptool` and `pyserial` (stated in its docstring); takes `--server http://<host>`, `--inventory <csv>`, `--bin` (default: the IDE's exported `TemperatureAlarms.ino.bin` under `build/` in the sketch folder), and the Admin token from the `ADMIN_TOKEN` environment variable, never a flag
- [x] It refuses to start when the binary is missing or older than any source file in the sketch folder, when `ADMIN_TOKEN` is unset, or when the server's `/api/health` does not answer
- [x] It is a watcher: started once, it polls the COM ports and handles each newly appeared port on its own thread, so a hub works several boards at once; Ctrl-C stops it after the boards in progress finish
- [x] Identify: esptool reads the MAC; the hostname is `ESP_` plus the MAC's last six hex digits upper-cased (what `network.cpp` derives from the chip id); the inventory row is looked up by MAC, and a board that is not on the sheet proceeds, flagged `not on list`
- [x] Register: a Campus named Bench with shortcode `BENCH` is created once if missing; the Device is registered under it with closet `Unassigned`; a 409 reads as already registered and is not a failure
- [x] Flash: the one binary at 921600 baud, falling back to 460800 when the handshake fails; ~~the sheet is the operator's and is never modified~~ (reversed 2026-09-10, see the comment: the sheet is the working record and is written back)
- [x] Bench check: pulse reset, read serial at 115200 for 70 seconds (two report attempts). PASS needs a `device:` line matching the derived hostname, `wifi: connected`, a `sensor:` line with numbers, and `report: 201 created`. No numeric `sensor:` line is FAIL bad sensor; no `device:` line is FAIL did not boot; both keep the batch going and leave the Device registered
- [x] Batch stops, loudly, on `report: 401` (the token in the binary), on no `wifi: connected` on the first board of the run (SSID or password), and on `report: failed` (the server is unreachable from the bench); the reason names which of the binary, the WiFi, or the server to fix
- [x] Log: one row per board seen, appended to `<inventory>.bench.csv` next to the sheet, with time, port, sheet row or blank, hostname, MAC, `registered` / `already`, `flashed`, verdict, and reason; replugging a board runs it again and adds a row. On stop it prints the sheet rows never seen and the boards seen that the sheet lacks
- [x] The one-line verdict per board on the terminal reads like the firmware's log, e.g. `COM7  row 12  ESP_7AED5B  registered  flashed  PASS` and `COM9  not on list  ESP_1234AB  already  flashed  FAIL bad sensor`
- [x] README firmware chapter gains a "Flashing a batch" subsection: install `esptool` with pip, export the binary once (one board type per batch, so one `DHT_PIN`), set `ADMIN_TOKEN`, run the watcher, read the log; and `CONTEXT.md` defines Bench
- [x] Tested without hardware: the sheet lookup, hostname derivation, binary staleness check, serial verdict parsing (PASS, each FAIL, each batch stop) and the reconciliation lists have unit tests on Python's own `unittest`, run with `python -m unittest arduino/test_bench.py`; the esptool and serial layers are behind one seam the tests fake. A real board is the acceptance test on the bench

## Comments

**2026-09-10 — built; the real board is left to the bench.** `arduino/bench.py` (stdlib plus `esptool` and `pyserial`, both imported only where used so the tests run without them) and `arduino/test_bench.py` (46 cases on `unittest`). Written test-first at the seams the ticket names: hostname derivation and the MAC parse of esptool's output (v4 `MAC: ..` and v5's padded `MAC:      ..`), the sheet lookup (`Inventory`: any MAC spelling, header matched case-insensitively, a row without a MAC such as the note line at the bottom of the real sheet is not a board, a sheet without a MAC column is refused), `binary_problem` and `default_binary` (the newest export under `build/`), `judge` for the serial verdict (PASS, FAIL bad sensor, FAIL did not boot, FAIL when serial names another hostname, FAIL no wifi on a later board, FAIL with the status for any other report, STOP for 401, for no WiFi on the first board, and for `report: failed`), `reconcile`, and the one-board flow `check_board` through a fake `Tools` (registered/already, the 460800 fallback, both bauds failing is an ERROR row, a port esptool cannot talk to is an ERROR row). The watcher has its own tests with a scripted port list: ports present at start are ignored, a replugged board runs again, the first-board WiFi stop, a board that never booted does not count as the first board, and exit code 1 after a batch stop.

Decisions worth knowing:
- The sheet row in the line and the log is the row as the spreadsheet shows it, header on row 1, so the technician can read it off the gutter in Sheets; the sheet's own `ID` column is ignored.
- "First board of the run" means any board checked before one has shown `wifi: connected`, so a board that never booted does not use up the credentials check.
- The serial read ends early on a decisive line (`report: 201 created`, `report: 401`, `report: failed`); otherwise it runs the full 70 s.
- esptool runs as a subprocess per board (`python -m esptool --chip esp8266 --port COMx ...`) so threads never share its stdout; the underscore command names work in esptool 4 and, with a deprecation note, 5.4. The reset pulse before the check is esptool's own hard-reset sequence (DTR low, RTS pulsed).
- A port esptool cannot talk to (something else on the hub) gets an `ERROR` row and does not stop the batch. Any board whose MAC was read counts as seen for the reconciliation, whatever happened after.
- The Bench Campus create is attempted on every start (a 409 says it exists), so a wrong `ADMIN_TOKEN` is refused before a board is plugged in, not discovered board by board.
- esptool runs in its own process group so the console's Ctrl-C stops the watcher and not a flash in flight.
- The log is `<sheet stem>.bench.csv`, so `device_log - device_log.csv` gets `device_log - device_log.bench.csv`.

Verified here without a board: the startup refusals for a blank `ADMIN_TOKEN`, a missing binary, an unreachable server, and a wrong token; against the dev backend on :3001 the Bench Campus was created once and found on the second run, the real transport's `register` answered `registered` then `already`, and Ctrl-C printed the 92 never-seen rows. `arduino/**/build/` and `__pycache__/` are now gitignored.

**Code review** (Standards and Spec axes) caught, and this fixed: the wrong-token refusal only fired when the Bench Campus did not exist yet (now the create is always attempted); the first-board WiFi rule was decided when a board appeared, not when its log was judged, so two boards on a hub were both "first" (now asked at judge time); a board whose flash failed at both bauds was left out of the reconciliation (now any read MAC is seen); `unittest.main()` sat mid-file so `python arduino/test_bench.py` ran four tests (moved to the end); Ctrl-C would have reached an esptool child mid-flash (own process group); esptool output was decoded strictly in the console code page (now UTF-8, replacing). Left alone as judgement calls: `check_board` takes its collaborators as parameters rather than living on the watcher, since the tests drive it with fakes on its own; the verdict kinds are strings; the serial read ends early on a decisive line rather than always running the full 70 s.

**Open for the bench:** the acceptance test is a real board on Windows: `pip install esptool pyserial`, export the binary, set `ADMIN_TOKEN`, run the watcher, plug a board in, and read its line and the log row. If esptool cannot connect at all, add `--baud 115200` knowledge to the fallback list; if the reset pulse does not reboot the board, the serial log will show nothing and the row will read `FAIL did not boot`.

**2026-09-10 — the sheet is written back after all.** On the first bench run the user said the sheet is what the technician keeps the tested and flashed state in, so the "never modified" decision above is reversed. After each board `Inventory.record` rereads the sheet, sets `FLASHED` (TRUE or FALSE), `TESTED` (TRUE on PASS, FALSE on FAIL, untouched on STOP or ERROR), and a `BENCH` column with the verdict and date, appends a row with the next `ID` above any note line for a board the sheet lacks, and replaces the file in one step with CRLF endings; untouched rows go back as read, so edits between boards survive. The line then reads `added row 94` for such a board and the log carries the new row. A sheet that cannot be written (open in Excel) is said on the line, `(sheet not updated: ...)`, and the board is otherwise handled. Five tests at the `Inventory` seam plus the one-board flow; 52 in all. The README subsection says so. The district-server run later is a reflash with the same watcher against the other server.

**2026-10-04 — accepted on the bench; closed.** The watcher has run the real batch of 92 boards: 91 PASS, one FAIL bad sensor (README, "Flashing a batch", commit 715332e).
