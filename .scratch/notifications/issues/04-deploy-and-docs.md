## Comments

**2026-10-06 — built, by a supervised worker; awaiting review.** Spec: `.scratch/notifications/spec.md` (Deploy, Docs); config rules from ticket 01.

**What was built.** `compose.yaml` passes `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `NOTIFY_FROM`, `NOTIFY_TO`, `PUBLIC_URL`, and `NOTIFY_COALESCE_SECONDS` to `api`, each `${KEY:-}`, so an unset one arrives empty and `config.ts`'s `present()` reads it as unset; the demo needs nothing (its `.env.demo` has none, so it is off). The root `.env.example` lists them commented at the end; `backend/.env.example` already did (01). `deploy.sh` and `deploy.ps1`: `install` asks for the relay after the TLS-proxy question (blank: no email; `off` on an existing one turns it off), then security, port, whether it needs a login (user, and the password at a hidden prompt), sender, recipients, and the dashboard address (offered from the site URL), each checked as typed. Non-interactively, `--smtp-host`, `--smtp-port`, `--smtp-secure`, `--smtp-user`, `--notify-from`, `--notify-to`, `--public-url` on a new `.env`, or with `--reconfigure` on an existing one, like `--web-port` and `--set`. Each flag changes only its own setting; everything is checked before anything is written; `--smtp-host off` empties the whole group (one left set without `SMTP_HOST` would stop api). The password is read at the hidden prompt, or with `--yes` from the first line of stdin (in `deploy.ps1`, the first line piped to the script, in a session or under `-File`); `--smtp-password` is refused by name. `--smtp-user` again with nothing on stdin keeps the current password. With `--host`, the password is read once locally and handed to each server on its ssh stdin. `info` shows the relay, port, security, sender, recipients (or `off`), and `SMTP login USER / ********`, the password masked whole (the hex secrets' first-and-last-four would give away most of a chosen password); `--reveal` prints it. `NOTIFY_COALESCE_SECONDS` is a tunable (`--set`, the thresholds prompt), empty allowed. Docs: CONTEXT.md **Notification**; DEPLOYMENT.md "Email notifications" (questions for the mail admin: relay, allowed sender or service account, sender address, a distribution list; ports 587, 465, and 25 with the district firewall; the flags with the stdin password in bash and PowerShell; by hand; the half-set refusal; the test button), plus the `install` and `info` rows, the Setup note, and the manual-install table; README a feature line, a Deployment paragraph naming the flags and variables (it has no configuration table), and the two `/api/notifications` routes in the API table; the `deploy` skill's secrets rule and two rows.

**Decisions beyond the ticket.** The password is written to `.env` single-quoted, `SMTP_PASSWORD='...'`, which Compose reads literally, so `$`, `#`, spaces, double quotes, and backslashes survive (proved with `docker compose config` and inside a running api); a password holding a single quote is refused, since Compose's single quotes have no escape. `env_get`/`Get-EnvValue` strip that quoting. `env_set` now hands awk the value through its environment, since `awk -v` turned a backslash into an escape (harmless for the hex secrets, not for a password or `DOMAIN\user`). The other values are checked against `config.ts`'s rules, narrowed to characters `.env` cannot misread (bare addresses, a host name or IPv4, http(s) URLs, one line each). `--public-url` is required with `--smtp-host`, not guessed. `install` only writes `.env`, as before; `deploy` applies it. ADR 0008's box stays unticked: its status is owned by the agent on 02 and 03, so it is not changed here; everything else in that box (CONTEXT.md, DEPLOYMENT.md, README, the skill) is done.
